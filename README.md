# Домашняя работа №5: библиотека на PostgreSQL — расширенная версия

Разработай базу библиотеки и подготовь SQL для работы библиотекаря: каталог, читатели, выдачи, возвраты и отчёты. Объясни решения и проверь поведение транзакций в двух независимых подключениях.

**Плановая нагрузка: 6–8 часов самостоятельной работы для начинающего.** Основная SQL-часть рассчитана примерно на 6 часов 20 минут по плану ниже, без дополнительного Python. Фактическое время зависит от подготовки. Записывай своё время в docs/report.md.

Это расширение прежней работы. Схема и CSV изменились: создавай отдельную базу **library_extended**. Старую library и выполненные задания не удаляй. Если уже начал прежнюю версию, сохрани её в своём fork отдельным коммитом перед обновлением.

## Что понадобится

PostgreSQL, pgAdmin и Git. Основные темы: типы данных, первичные и внешние ключи, связи, SELECT, INSERT, UPDATE, DELETE, JOIN, ограничения, транзакции и ACID. Для дат используй DATE, для цены NUMERIC. В новом блоке сравнишь READ COMMITTED и REPEATABLE READ по готовой инструкции.

Агрегации, подзапросы, оконные функции, триггеры, HTTP и автоматические тесты не требуются. Python — дополнительное задание после основной работы.

## Порядок выполнения

1. Сделай fork, скачай его и прочитай [требования к схеме](docs/schema.md). Заполни [описание модели](docs/model.md): одна строка каждой таблицы, ключи, виды связей и назначение таблицы book_authors.
2. Заполни sql/00_create_database.sql и выполни создание library_extended в Query Tool для существующей базы postgres. CREATE DATABASE запускается отдельно, вне BEGIN/COMMIT.
3. Открой новое окно Query Tool для library_extended. Проверь текущую базу. Затем выполняй файлы 01–07 по порядку.
4. Загрузку CSV преврати в SQL INSERT самостоятельно. Первая строка CSV задаёт порядок столбцов. Пустая ячейка email или returned_date означает SQL NULL, не строку 'NULL'. True/False — логические значения. Даты заданы в формате YYYY-MM-DD. Исходные CSV не изменяй.
5. Все таблицы находятся в public. В запросах указывай public явно. CREATE TABLE и исходные INSERT рассчитаны на один запуск в новой учебной базе.
6. Дату для всех отчётов зафиксируй: **2026-06-01**. Не используй CURRENT_DATE для этих условий, иначе результаты изменятся со временем.
7. [Контрольные результаты](docs/checkpoints.md) относятся к исходным данным до задания 7. Задание 5 заканчивается откатами, задание 6 не должно менять данные. Для SQL-запросов 3–4 всегда задавай указанный порядок строк.
8. Для задания 8 используй две независимые сессии по [инструкции](docs/isolation-guide.md). Этот файл нельзя выполнять целиком: команды запускают по шагам в нужном окне.
9. Выполни отладку 9, ответы 10 и заполни [отчёт](docs/report.md). Проверочные SELECT тоже сохрани в соответствующих файлах SQL.

## Основные задания

Полные формулировки каждого запроса и сценария уже находятся в комментариях файлов sql/. Под каждым TODO напиши решение. Сохраняй нумерацию, чтобы преподаватель мог найти ответ.

- **Модель и таблицы:** шесть таблиц, в том числе связь книг и авторов многие ко многим. Полные поля и ограничения находятся в docs/schema.md. Не вводи UNIQUE для имени читателя: в данных есть две Алисы.
- **Данные:** 12 читателей, 7 авторов, 5 категорий, 10 книг, 13 пар книга/автор и 16 выдач. copies уже учитывает исходные выдачи; повторно уменьшать его при загрузке не нужно.
- **SELECT и JOIN:** фильтрация по датам, доступным экземплярам, статусу и цене; отчёты по просрочкам и поиску сущностей без связанных строк. Один JOIN с авторами может давать несколько строк на книгу — объясни причину.
- **Изменения:** работа с временными читателями, книгами и категориями. Каждый сценарий задания 5 заверши ROLLBACK, чтобы не испортить исходные отчёты.
- **Ограничения:** для каждого из 12 случаев нарушай только одно указанное правило. Используй свободные id и корректные остальные поля. Проверяй команды по одной вне BEGIN при включённом Auto commit. Сохраняй сообщение или SQLSTATE и объяснение в отчёте. Перед сдачей ошибочные команды должны быть закомментированы.
- **Транзакции:** сначала откат выдачи и намеренная ошибка, затем подтверждённая выдача 200 и её возврат. После этого в loans 17 строк, выдача 200 закрыта, copies книги 10 снова 3. Условное UPDATE без изменённых строк не означает успешную выдачу или возврат: посмотри число строк и прими решение вручную по условию задания.
- **Изоляция:** сравни видимость неподтверждённых и подтверждённых изменений при READ COMMITTED и REPEATABLE READ. После опытов верни copies книги 80 к 5 и заверши обе транзакции.
- **Отладка:** исправь шесть примеров с NULL, JOIN, фильтром, отсутствующим WHERE, синтаксисом CREATE TABLE и датами. Изменения выполняй с откатом.

Намеренная ошибка внутри транзакции в задании 7 может остановить выполнение скрипта до ROLLBACK. Запусти ROLLBACK отдельно. Перед сдачей закомментируй весь этот ошибочный сценарий Б. Остальные сценарии оставь исполняемыми. Скрипт 08_isolation.sql сдаётся как последовательность помеченных шагов для двух сессий, а не как один пакет.
