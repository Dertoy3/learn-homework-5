# Домашняя работа №5: PostgreSQL и база библиотеки

Создай базу библиотеки: читатели, книги и выдачи. Напиши SQL для создания таблиц, добавления данных, поиска и изменения записей. Отработай ограничения и транзакции.

Нужны PostgreSQL и pgAdmin. Основная часть выполняется в Query Tool. Python понадобится только для дополнительного задания.

## Структура

```text
sql/
    00_create_database.sql   # Создание базы
    01_tables.sql            # Таблицы и ограничения
    02_data.sql              # Исходные данные
    03_select.sql            # SELECT, WHERE, ORDER BY, LIMIT
    04_join.sql              # Связанные таблицы
    05_changes.sql           # INSERT, UPDATE, DELETE
    06_constraints.sql       # Примеры нарушения ограничений
    07_transactions.sql     # ROLLBACK и COMMIT
    08_answers.sql           # Ответы на вопросы
data/
    readers.csv
    books.csv
    loans.csv
find_reader.py               # Дополнительное задание с Psycopg
main.py                      # Готовый запуск дополнительного задания
requirements.txt
```

В SQL-файлах оставлены условия и TODO. Напиши команды под соответствующими комментариями. В CSV лежат исходные данные для задания: используй их для составления INSERT. Автоматически импортировать CSV не требуется. В readers.csv пустой email означает SQL NULL.

## Как работать

1. Сделай fork репозитория и скачай свой fork на компьютер.
2. Открой `sql/00_create_database.sql` в Query Tool для существующей базы `postgres`. Напиши команду создания базы `library` и выполни её отдельно, вне транзакции.
3. Обнови список Databases в pgAdmin. Открой новое окно Query Tool именно для `library`.
4. Выполняй файлы `01_tables.sql`–`08_answers.sql` по порядку. Все таблицы создавай в схеме `public` и указывай её в запросах.
5. Создание таблиц, добавление исходных данных и примеры с фиксированными id рассчитаны на однократное выполнение в новой учебной базе.

Не удаляй существующие базы и чужие таблицы. Если база `library` уже занята, выбери другое имя и используй его во всех подключениях. После выполнения обнови `Schemas → public → Tables`.

## 1. Таблицы и ограничения

Файл `sql/01_tables.sql`. Создай таблицы в порядке `readers`, `books`, `loans`.

| Таблица | Поле | Тип и требования |
| --- | --- | --- |
| readers | id | INTEGER, PRIMARY KEY |
| readers | name | TEXT, NOT NULL |
| readers | email | TEXT, UNIQUE, может быть NULL |
| books | id | INTEGER, PRIMARY KEY |
| books | title | TEXT, NOT NULL |
| books | copies | INTEGER, NOT NULL, DEFAULT 0, CHECK: не меньше 0 |
| loans | id | INTEGER, PRIMARY KEY |
| loans | reader_id | INTEGER, NOT NULL, внешний ключ на readers(id) |
| loans | book_id | INTEGER, NOT NULL, внешний ключ на books(id) |
| loans | returned | BOOLEAN, NOT NULL, DEFAULT FALSE |

Идентификаторы задавай вручную. Внешние ключи должны запрещать ссылку на несуществующего читателя или книгу. При удалении связанных записей используй стандартное поведение внешних ключей, без CASCADE.

## 2. Исходные данные

| 1 | Алиса | alice@example.test |

`copies` — число доступных экземпляров на текущий момент, после перечисленных выдач. При добавлении исходных данных повторно уменьшать его не нужно. Автоматический пересчёт copies и триггеры в этом задании не нужны.

Самостоятельно проверь: 4 читателя, 3 книги, 3 выдачи.

## 3. SELECT и фильтрация

Файл `sql/03_select.sql`. Отдельный запрос для каждого пункта:

1. Все читатели, сортировка по имени, затем id.
2. Только названия книг и copies, сортировка по id книги.
3. Книги, у которых copies больше 0, сортировка по id.
4. Читатели без email, сортировка по id.
5. Одна книга с максимальным copies. При равенстве выбери книгу с меньшим id.

Для отсутствующего email используй IS NULL. Пустая строка и NULL — разные значения.

## 4. JOIN

3. Читатели, у которых никогда не было выдач. Используй LEFT JOIN, выведи id и name, порядок по id читателя.

Для проверки третьего запроса: Олег и Ирина. В первом запросе должно быть 3 строки, во втором — 2.

После каждого действия выполни SELECT по id=5. Для UPDATE и DELETE обязательно задай WHERE. В конце в readers снова должно быть 4 строки. Остальных читателей не изменяй.

## 6. Проверка ограничений

Файл `sql/06_constraints.sql`. Подготовь по одной команде, которая нарушает:

1. PRIMARY KEY: повтор id существующего читателя.
2. CHECK: книга с copies=-1.
3. FOREIGN KEY: выдача несуществующему читателю.
4. NOT NULL: читатель с name=NULL.

В каждом примере нарушай только указанное правило: остальные значения должны быть корректными, а новые id свободными. Выполняй примеры отдельно при включённом Auto commit в pgAdmin, вне BEGIN. Если осталась прерванная транзакция, сначала выполни ROLLBACK.

Запиши причину каждой ошибки комментарием. Перед сдачей закомментируй сами ошибочные команды, чтобы они не прерывали запуск остальных файлов.

## 7. Транзакции

Файл `sql/07_transactions.sql`. Олег берёт «Основы Python»:

1. Начни транзакцию.
2. Уменьши copies книги id=10 на 1.
3. Добавь выдачу id=103: reader_id=3, book_id=10, returned=FALSE.
4. Выполни ROLLBACK.
5. Проверь: copies=3, выдачи id=103 нет.
6. Повтори действия в новой транзакции и выполни COMMIT.
7. Проверь: copies=2, выдача id=103 существует.

Обе операции внутри каждой транзакции должны изменять данные вместе. Проверочные SELECT располагай после ROLLBACK и после COMMIT. Весь файл рассчитан на один запуск после предыдущих заданий.

## Дополнительно. Параметры в Python

Реализуй `find_reader(reader_id)` в `find_reader.py`:

1. Подключись к базе library через Psycopg. Параметры подключения получи из окружения: PGHOST (по умолчанию localhost), PGPORT (5432), PGDATABASE (library), PGUSER (postgres).
2. Пароль запроси через getpass.getpass при каждом вызове функции. Не записывай пароль в репозиторий.
3. Найди name читателя по id. Используй `%s` и отдельный кортеж параметров.
4. Верни строку с именем или None, если id не найден. Соединение должно закрываться через with.
5. Не подставляй id через f-строку и не склеивай его с SQL.

Установка и запуск из папки проекта:

```text
python -m pip install -r requirements.txt
python main.py
```

`main.py` уже спрашивает id, вызывает функцию и выводит результат. Для id=1 ожидается Алиса, для id=999 — сообщение «Читатель не найден». При вводе нецелого id main выводит понятное сообщение и завершается. Если функция ещё не реализована, main сообщает об этом. Ошибки подключения не подменяй результатом None.

Если выбрал другое имя базы, задай PGDATABASE перед запуском. В PowerShell: `$env:PGDATABASE = "имя_базы"`.
