# Подсказка к экспериментам с изоляцией

Открой два отдельных Query Tool одной базы. Разные вкладки внутри одного редактора не гарантируют разные соединения: проверь pg_backend_pid().

Не запускай весь сценарий одним нажатием. В каждом шаге смотри, какую сессию нужно использовать. В Б первый SELECT должен произойти раньше COMMIT в А.

Синтаксис начала транзакции с уровнем:

```sql
BEGIN ISOLATION LEVEL READ COMMITTED;
```

или

```sql
BEGIN ISOLATION LEVEL REPEATABLE READ;
```

Завершение: COMMIT или ROLLBACK. Вне явных транзакций оставь Auto commit включённым. Не меняй настройки уровня глобально на сервере.

В READ COMMITTED каждый запрос видит снимок подтверждённых данных на начало запроса. В REPEATABLE READ снимок закрепляется первым запросом или изменением данных внутри транзакции, а не самим BEGIN. В обоих опытах Б только читает книгу, а А её изменяет: это важно для простого сравнения без конфликтующих UPDATE.

Если перепутал шаги, заверши активные транзакции в обеих сессиях, верни copies книги 80 к 5 и повтори опыт. Восстанавливай только специально используемую учебную строку.

Источник: [PostgreSQL 18 — Transaction Isolation](https://www.postgresql.org/docs/18/transaction-iso.html).
